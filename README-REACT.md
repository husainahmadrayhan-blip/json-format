# অফলাইন React জন্মতথ্য JSON পার্সার (v51)

## Windows-এ চালানো

1. ZIP-টি **Extract All** করুন। `offline-ollama-parser` ফোল্ডারের ভেতরে terminal / Command Prompt খুলুন।
2. `npm start` লিখে Enter চাপুন। এটি Python 3 শনাক্ত করে একই ফোল্ডারের লোকাল সার্ভার চালু করবে; BAT ফাইল দরকার নেই।
3. terminal-এ `v51-name-colon-normalization: খুলুন http://127.0.0.1:PORT/index.html?v=51` যে ঠিকানা দেখা যায়, সেটিই ব্যবহার করুন। ব্রাউজার নিজে না খুললে ঠিকানাটি কপি করুন।
4. পেজে `v51-name-colon-normalization চালু` দেখা গেলে লেখা পেস্ট করে `নিয়ম দিয়ে JSON` চাপুন। Ollama লাগলে স্থানীয় Ollama চালান, মডেল বেছে `নিয়ম → দরকারে Ollama` চাপুন।
5. তথ্য যাচাই করে সম্মতির ঘরে টিক দিয়ে JSON কপি বা ডাউনলোড করুন। বন্ধ করতে terminal-এ Ctrl+C চাপুন।

চালানোর জন্য Node.js ও Python 3 দরকার। React-এর প্রস্তুত `dist/` ফাইল ZIP-এর মধ্যেই আছে; `npm start` করতে `npm install`, ইন্টারনেট বা API key লাগে না। Ollama স্থানীয়ভাবে চালালে AI fallback পাওয়া যায়।

## উৎস কোড

`src/main.jsx` ও `src/style.css` React অ্যাপ; `server.py`, `rules.py`, `address_geo.py` এবং `BDRIS_MASTER_GEO.json` পুরোনো Python backend ও Geo Data। ইন্টারনেট/লোকাল npm cache থাকলে কোড সম্পাদনার পরে `npm install` এবং `npm run build` দিয়ে `dist/` নতুন করে তৈরি করুন। চালানোর সময় Python সার্ভার কেবল `dist/` দেখায়।

## ঠিকানা ও ডেটা সতর্কতা

Geo Data-তে মেলা জেলা/উপজেলা/ইউনিয়ন/ওয়ার্ড নেওয়া হয়। দেওয়া জায়গা Geo hierarchy-তে না মিললে ফিল্ড খালি রাখা ও সতর্কতা দেখানো হয়। ফিল্ড অনুপস্থিত থাকলে Geo Data-র সংশ্লিষ্ট প্রথম বৈধ child **প্রস্তাব** হতে পারে; তা প্রকৃত বাসস্থানের প্রমাণ নয়। Geo Data-তে গ্রাম/ডাকঘর নেই, তাই ইনপুটে না থাকলে সেগুলো খালি। লোকাল নিয়মে স্পষ্ট তথ্য পাওয়া গেলে Ollama লাগে না; Ollama দিয়ে কেবল অনিশ্চিত ফিল্ড চেষ্টা করা হয়। সবার শেষে মূল লেখার সঙ্গে মিলিয়ে নিন।

প্রতিবার `npm start` দিলে নতুন পোর্ট হতে পারে। আগের ট্যাব নতুন সার্ভারের নয়।

## একাধিক ঠিকানা এবং Geo নির্বাচন

একই লেখায় বরিশাল ও খুলনা থাকলে জন্মস্থানের জন্য দুটি জেলা অপশন আসে। একটি বাছা পর্যন্ত `birthPlace` খালি থাকে। জেলা বাছলে ওই জেলার বিভাগ এবং Geo Data-এর অধীনে উপজেলা → ইউনিয়ন → ওয়ার্ড পর্যায়ক্রমে নেওয়া হয়। লিখিত মান ওই ধাপে মিললে সেটি নেওয়া হয়; ধাপ অনুপস্থিত বা না মিললে ওই জেলার ভেতরের Geo branch থেকে একটি বৈধ মান বসানো হয়। Dropdown-এ উপজেলা/ইউনিয়ন/ওয়ার্ড বদলানো যায়।

ডাকঘর ও গ্রাম ইনপুটে থাকলে লিখিত বাংলা ও ইংরেজি মান রাখা হয়। অনুপস্থিত হলে ব্যবহারকারীর নির্দিষ্ট ডিফল্ট: ডাকঘর `চন্দ্র নগর` / `Chondon Nogor`; গ্রাম `সাতকাপন` / `Satkapon`। এগুলো Geo Data-র যাচাইকৃত ডাকঘর বা গ্রাম নয়; ব্যক্তির প্রকৃত ঠিকানা বলে দাবি করা যাবে না। সার্ভার ঠিকানার অমিল নিয়ে সতর্কবার্তা দেখায় না, তবে কোন ফিল্ড Geo বা ডিফল্ট থেকে এসেছে পেজে তা চিহ্নিত থাকে।

কমা দিয়ে এক লাইনে লেখা `Village: Choyom Tatka, Hesamoddi-8270, Mehendiganj, Barishal` আলাদা গ্রাম, ডাকঘর/পোস্টকোড, উপজেলা, জেলা হিসেবে ধরা হয়। বাংলা ও ইংরেজি একই ঠিকানা পরপর থাকলে পোস্টকোড মেলে এবং দুটি ভাষার তথ্য পরিপূরক হলে একটি জন্মস্থানের অপশনে একত্র হয়। জেলা বাছলে কেবল সেই ঠিকানা birthPlace-এ যায়।

`জন্মস্থান : চট্টগ্রাম` বা `Birth place: CHATTOGRAM` লিখলে জেলা সরাসরি চট্টগ্রাম ধরে জন্মস্থানের বিভাগ এবং Geo hierarchy ও ঠিকানার নির্ধারিত ডিফল্ট পূরণ হবে।

জেলা শনাক্তকরণ শুধুমাত্র `জেলা:` বা `জন্মস্থান:` লেবেলে সীমিত নয়। ঠিকানার লাইন, কমায় ভাগ করা অংশ, এবং একই লাইনে উপজেলা ও জেলার Geo নাম মিলিয়ে জেলার প্রার্থী বের করে। `বিভাগ:` লাইনের নাম বা `উপজেলা: কিশোরগঞ্জ সদর` থেকে ভুল করে জেলা প্রার্থী তৈরি করা হয় না। একই জেলার বাংলা/ইংরেজি পুনরাবৃত্তি একত্র হয়; ভিন্ন জেলা/ঠিকানার অংশ আলাদা অপশন থাকে। এটা সব অজানা ফরম্যাটে শতভাগ সঠিকতার দাবি নয়; ডেটা যাচাইয়ের ঘর রাখা আছে।

ডাকঘর, গ্রাম ও বাসা/হোল্ডিং লেখায় থাকলে বাংলা/ইংরেজি মূল মান আলাদা ফিল্ডে নেওয়া হয়। `★গ্রাম`, `গ্রাম (বাংলা)`, `Post Office with Code`, `P.O`, একই লাইনে একাধিক অংশ, বাংলা-ইংরেজি আলাদা ব্লক, এবং ওয়ার্ডের পর লেবেলবিহীন বাংলা-ইংরেজি ডাকঘর/গ্রাম এই সংস্করণে শনাক্ত হয়। শুধু অনুপস্থিত ডাকঘর/গ্রামের ভাষাভিত্তিক মানে ব্যবহারকারী নির্ধারিত ডিফল্ট বসে; বাড়ি অনুমান করা হয় না। `python verify_addresses.py` চালিয়ে স্থানীয় regression checks করা যায়।

## বাংলা নাম থেকে ইংরেজি বানান

ডাকঘর বা গ্রামের বাংলা নাম পাওয়া গেলে কিন্তু ইংরেজি না থাকলে অফলাইনে ইংরেজি লিপ্যন্তর দেওয়া হয়। Geo Data-তে অনন্য বাংলা-ইংরেজি নাম থাকলে সেই বানান ব্যবহার হয়; অন্যথায় স্থানীয় নিয়মে বানান তৈরি হয়। ইংরেজি আগে লেখা থাকলে তা বদলায় না। তৈরি বানানের পাশে “বাংলা থেকে ইংরেজি” দেখাবে; এটি আনুষ্ঠানিক ইংরেজি বানানের নিশ্চয়তা নয়, তাই মিলিয়ে নিন। বাংলা-ইংরেজি কোনোটিই না থাকলেই পূর্বনির্ধারিত মান বসে।

## অফিস ঠিকানা

v20 ফাইলের ১০টি প্রস্তুত অফিস ঠিকানা React পেজে Parse-এর আগেই দৃশ্যমান। নতুন অফিসও Parse-এর আগে সংরক্ষণ করা যায়। প্রতিটি ছোট অফিস কার্ডে দুটি বোতাম: **৩ ঠিকানায় অফিস** জন্মস্থান, স্থায়ী ও বর্তমান ঠিকানায় ওই অফিসের ঠিকানা বসায়; **স্থায়ী + বর্তমান অফিস** শুধু স্থায়ী ও বর্তমান ঠিকানা বসায় এবং আগের জন্মস্থান রাখে। দুটি বোতামই Parse-এর পর এক ক্লিকে JSON প্রিভিউ বদলায়। একই অফিসের স্থায়ী ও বর্তমান ঠিকানা v20-তে আলাদা থাকলে নিজ নিজ মান ব্যবহৃত হয়। অন্য JSON তথ্য অপরিবর্তিত থাকে। ভুল ক্লিকের পরে অন্য বোতাম চাপলে জন্মস্থান আগের Parse করা/বাছা মানে ফিরে যায়। “নতুন অফিস ঠিকানা যোগ” দিয়ে নাম এবং ঠিকানার JSON লিখে ব্রাউজারে সংরক্ষণ করুন। অফিসের মান ব্যবহার করার আগে যাচাই করুন। `node verify_offices.mjs` দিয়ে দুটি নির্বাচন পরীক্ষা করা যায়।

নতুন কার্ড “অঞ্চল - ১০ / মধ্য বাড্ডা”-তে ঢাকা উত্তর সিটি কর্পোরেশন, অঞ্চল - ১০, ওয়ার্ড ৩৮, বাড্ডা - ১২১২, মধ্য বাড্ডা এবং বাড়ি ৫৫৬৫ দেওয়া আছে; ইংরেজি মান ব্যবহারকারীর লেখা অনুযায়ী রাখা হয়েছে।

## ঐচ্ছিক Groq API (ইন্টারনেট)

Groq API key দিয়ে পেজের **নিয়ম → দরকারে Groq** ব্যবহার করুন। মডেল `openai/gpt-oss-20b`; উত্তরে strict JSON schema চাওয়া হয়। বিকল্প: Windows CMD-তে `set GROQ_API_KEY=আপনার_key` বা PowerShell-এ `$env:GROQ_API_KEY='আপনার_key'` দিয়ে একই terminal থেকে `npm start` চালান। Browser key স্থায়ীভাবে রাখে না। প্রয়োজনীয় ফিল্ড খালি থাকলেই মূল লেখা Groq-তে যাবে। অফলাইনের নিয়ম/Ollama আলাদাভাবে চলবে।

আবেদনকারীর জন্মতারিখ ২০১৩ বা পরের হলে, পিতা-মাতার সেকশনে স্পষ্টভাবে লেখা ১৭ অঙ্কের জন্মনিবন্ধন নম্বর ও জন্মতারিখ আগে লোকাল নিয়মেই নেওয়া হয়। যা খালি থাকে, Groq শুধু সেটিই চেষ্টা করবে। উৎসে না থাকলে খালি থাকবে; ২০১৩ সালের আগের আবেদনকারীর parent BRN/DOB এই মাধ্যমে পূরণ হবে না। নামের বানান, নম্বর, তারিখ ও ব্যক্তি মূল লেখার সঙ্গে মিলিয়ে দেখা হয়। সন্তানক্রম মূল লেখা থেকে, না থাকলে `"4"`; পিতা-মাতার nationality সবসময় `"1"`; ঠিকানা শুধু আগের স্থানীয় Geo/অফিস নিয়মে। প্রতিদিনের ফ্রি quota বা বিলমুক্ত API ব্যবহার নিশ্চিত নয়; Groq account-এর বর্তমান limits দেখে নিন। `python verify_groq.py` দিয়ে key ছাড়াই contract পরীক্ষা করুন।

ডাকঘর/গ্রাম কেবল ইংরেজিতে থাকলে বাংলা ঘরে স্থানীয় নামের বাংলা বানান তৈরি হয়, আর কেবল বাংলায় থাকলে ইংরেজি ঘরে রোমান বানান তৈরি হয়। মিলে গেলে Geo Data-র বাংলা-ইংরেজি বানান নেওয়া হয়; অন্য নতুন বানান আনুমানিক প্রতিবর্ণীকরণ, মূল লেখার আনুষ্ঠানিক অনুবাদ নয়। পোস্টকোড বাংলা ঘরে বাংলা অঙ্ক ও ইংরেজি ঘরে ইংরেজি অঙ্কে থাকে। দুটো ভাষা লেখা থাকলে দুটোই সংরক্ষিত থাকে।

## Groq-এর বিকল্প: Gemini API

[Google AI Studio](https://aistudio.google.com/apikey) থেকে **নতুন Gemini API key** নিয়ে অ্যাপের Gemini key ঘরে দিন এবং **নিয়ম → দরকারে Gemini** চাপুন। Groq-এর key এখানে ব্যবহার করা যায় না। Gemini 2.5 Flash structured JSON দিয়ে একই খালি ব্যক্তিগত ফিল্ড চেষ্টা করে; প্রতিটি প্রস্তাব মূল লেখার সঙ্গে মিলিয়ে নেওয়া হয়। ঠিকানা/সন্তানক্রম/জাতীয়তা AI বদলায় না। Windows CMD-তে চাইলে `set GEMINI_API_KEY=আপনার_key` ব্যবহার করুন। Key ZIP-এ রাখা হয় না। Gemini quota, free tier ও availability অ্যাকাউন্টভেদে বদলাতে পারে। `python verify_gemini.py` দিয়ে API key ছাড়াই route পরীক্ষা করা যায়।

## Ollama-র উৎস যাচাই

Ollama-ও এখন কেবল খালি ব্যক্তিগত ফিল্ড পায়; উত্তরের প্রতিটি মান মূল লেখার নির্দিষ্ট লাইন ও সঠিক ব্যক্তির সঙ্গে মিললে JSON-এ নেওয়া হয়। অন্য ব্যক্তির জন্মতারিখ, বানানো নাম/নম্বর অথবা দেওয়া লেখার সঙ্গে না মেলা মান বাদ যায়। সন্তানক্রম, nationality এবং Geo/অফিস ঠিকানা Ollama বদলাতে পারে না। আবেদনকারীর জন্ম ২০১৩ বা পরে হলে পিতা-মাতার স্পষ্ট BRN/জন্মতারিখ আগে লোকাল নিয়মেই বসে। `python verify_ollama.py` দিয়ে key ছাড়াই পরীক্ষা করুন।

## নাম ঠিক করার নিয়ম (v51)

`পিতার ঃঃ ...` বা `মাতার : ...` লাইনের লেবেল আর নামের অংশে ঢোকে না। বাংলা নামের `মো:` → `মোঃ`, `মোছা:` → `মোছাঃ`, `মোসা:` → `মোসাঃ` হয়। পার্স করা তথ্য দেখানোর সময় এবং নামের ঘর সম্পাদনার সময় একই নিয়ম কাজ করে। প্রতিটি নামের ঘরের ✔️ বোতাম ক্লিক করলে নামের শেষে একটি ইংরেজি apostrophe (`'`) যোগ হয়, পুনরায় ক্লিক করলে মুছে যায়; খালি নামে বোতাম নিষ্ক্রিয়। এটি ব্যবহারকারীর ঐচ্ছিক সম্পাদনা।
